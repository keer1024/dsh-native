## 需求（原文，逐条编号，勿改写）

- R1「你忽悠我呀，界面上哪里可以看到工具开关？」（m01681，2026-11-05 14:36）
  - 前一次（m01036）同样抱怨「依旧没有找到工具管理开关」。1.7.7 把开关做进了 **设置 → 插件 → dsh-rust-exec 分页**的底部，用户在界面上找不到它 —— 这是**位置错**，不是功能没做。
  - 用户口中的「监控管理页面」= 点会话输入框底部缩略信息打开的 `MonitorDialog`。开关必须出现在这个窗口里。

## 根因（已确认）

1. `ToolsCard` 只挂在 `RustExecPanel`（slot `settings.plugins.tab`），需要用户先找到插件分页、再滚过 Concurrency + Feature switches 两屏。
2. `MonitorDialog` 里只有曲线与节省报表，没有任何管理入口。
3. 另一处会误导：`progressive disclosure` 打开时懒加载的工具（rust_edit/rust_stat/rust_ls/rust_symbols/rust_session_open）本来就不在注册表里，1.7.7 一律显示「已关闭」——把「懒加载」说成「被关掉」是错的。

## 改动

- `packages/dsh-rust-exec/client.js`
  - `MonitorDialog` 顶部（标题行下、曲线之上）渲染 `ToolsCard`：打开弹窗第一眼就是 11 个开关。
  - `ToolsCard` 由「照 props 渲染」改为本地镜像 `local`（`useState` + `useEffect` 同步）：弹窗的轮询不带 nonce，点完开关必须立刻变，不能等下一拍；成功后以宿主回执 `body.tools` 为准，回执缺失才本地翻转。
  - `ToolsCard` 新增 `wanted`（`/metrics.config.tools`，用户意图）与三态文案：`已注册` / `已关闭` / `未加载 · 用到时才注册`。懒加载不再冒充「已关闭」。
- `tools/monitor_render_test.mjs`
  - METRICS fixture 增加 `tools`（11 键）；fetch 桩区分 GET/POST 并记录 `POSTS`，`/config` 返回 `{ applied, tools }` 并按请求更新 fixture。
  - 新增「=== per-tool switches live in the monitor dialog ===」：开关卡片在弹窗内、11 行、`role="switch"`、点 rust_write 只 POST 这一项、不靠轮询就变、懒加载 vs 主动关闭的文案两分。
