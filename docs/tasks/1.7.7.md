## 根因初判（12:00 开工先验，勿当结论）

1. `MonitorDialog` 根节点是 `position: fixed; inset: 0; zIndex: 2147483000`（`packages/dsh-rust-exec/client.js:1991`），但**没有 portal**，而是直接挂在 dock / 会话视图的 React 树里。
   - 任何祖先带 `transform` / `filter` / `backdrop-filter` / `contain: paint` / `will-change: transform`，都会让 `fixed` 相对该祖先定位 → 弹窗贴在会话底部，而不是视口中央。
   - 同理，滚轮事件落在这个祖先的滚动容器里 → 弹窗滚动时把会话页面一起滚（scroll chaining）。
2. 宿主自己的做法是把浮层 portal 到 `document.body`：`require('react-dom').createPortal(node, document.body)`。证据：`.tmp/native/dsh/node_modules/@deepseek-ai/dsh-client-ui-schedule/lib/client.js:1888`（`createPortal(...)`）+ `:1966`（`}), document.body)`）；同文件 `:2905/:2915` 是第二处。插件侧 `factory(require)` 走同一个 loader，`require('react-dom')` 可用（该文件 `lib/client.js:8` 即 `require("react-dom")`）。
3. 轮子隔离需要两件事，缺一不可：弹窗容器 `overscrollBehavior: 'contain'`（到边界也不链到父级），以及打开期间锁 body 滚动（记录并恢复 `scrollY`，关闭时还原）。
4. R2 不再查「找不到」，改成新做逐工具开关。关键 API：宿主 `ctx.tools.register(definition)` **返回精确的 disposer**（`.tmp/native/dsh/node_modules/@deepseek-ai/dsh-tools/lib/index.js:2972-2982`，注释原文「returns the exact disposer that unregisters the tool」，实现 `this.layers.effect(this.ctx, (layer) => layer.tools.insert(name, definition), { label: "tools.register()" })`）→ 逐工具启停可以**免重新加载**实时生效：注册时把 disposer 按工具名存起来，关掉就调 disposer，打开就重新 register。
   - 持久化：沿用 1.7.6 的 `POST /config` + `settings.json` 落盘（`<pluginStateDir>/config.json`），新增 `tools` 对象（缺省全开，避免升级后工具直接消失）。
   - 面板：设置 → 插件 → dsh-rust-exec 增加「工具管理」分组，逐行 `工具名 + 开/关 + 现值`；状态要与 `/metrics` 回报的真实注册表一致，不能只信 settings.json。
